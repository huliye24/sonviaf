# Sonviaf 导入歌曲后的交互流程 V1

**文档状态：** 产品交互规范  
**适用范围：** Sonviaf Web / Studio 原型  
**产品主链：** `Upload → Work → Separate → Sing → Performance → Verify → Publish`  
**核心原则：** 用户通过图标、按钮和状态完成任务；界面不以大段说明文字代替操作。

## 1. 这份文档解决什么问题

用户已经导入一首歌后，不应该面对“先让文件成为作品”之类需要理解产品内部概念的大段文字。界面必须直接回答三件事：

1. 这首歌现在是什么状态；
2. 下一步可以做什么；
3. 点击后会发生什么。

Sonviaf 不把上传成功等同于作品完成，也不自动启动分轨。上传完成后，系统创建一个可追溯的 Work 草稿，保留原始音频，并把用户带到作品操作台。

## 2. 上传完成后的第一屏

### 2.1 页面目标

让用户不用阅读说明，就能听见原曲并选择下一步动作。

### 2.2 页面布局

```text
┌────────────────────────────────────────────────────────────────┐
│ Sonviaf     搜索                                      ＋ 导入   │
├──────────────┬─────────────────────────────────────────────────┤
│              │  封面   歌名                         ···        │
│  作品库      │         原始音频 · 02:53 · 已导入               │
│              │                                                 │
│  当前作品 ●  │  [播放] ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 02:53      │
│  其他作品    │                                                 │
│              │  [分轨]   [制作伴奏]   [演唱]   [导出]          │
│              │                                                 │
│              │  最近版本 / 当前任务 / 处理状态                 │
└──────────────┴─────────────────────────────────────────────────┘
```

页面只保留一个作品标题。不要再显示“01/7”“STEP 01”“建立作品”等重复文本，也不要在主区域放置大段产品解释。

### 2.3 默认可见控件

| 位置 | 图标/按钮 | 标签 | 点击结果 |
|---|---|---|---|
| 标题左侧 | 封面缩略图 | 无 | 打开封面/作品信息 |
| 播放栏 | `▶ / ❚❚` | 无 | 播放或暂停原始音频 |
| 主操作区 | 分层波形图标 | `分轨` | 打开分轨任务确认层 |
| 主操作区 | 去人声/伴奏图标 | `制作伴奏` | 若无 Stem，提示先分轨；若已有 Stem，进入伴奏编辑 |
| 主操作区 | 麦克风图标 | `演唱` | 若无伴奏，提供“先制作伴奏”；若已有伴奏，进入演唱准备 |
| 主操作区 | 下载图标 | `导出` | 打开可导出资产列表；没有成品时仍允许导出原作 |
| 标题右侧 | `···` | 无 | 改名、编辑信息、查看来源、导出原作、删除 Work |

## 3. 用户导入歌曲以后做什么

### 路径 A：我要把歌拆开

用户点击主按钮 `分轨`。

弹出的确认层只包含：

- 分轨类型：`人声 + 伴奏`（默认）或 `人声 / 鼓 / 贝斯 / 其他`；
- 对原作的保证：原始音频不会被覆盖；
- 一个主按钮：`开始分轨`；
- 一个次按钮：`取消`。

点击 `开始分轨` 后：

1. 主按钮变为进度按钮，例如 `分轨中 36%`；
2. 作品库条目出现旋转状态图标；
3. 用户可以离开当前页面，任务继续；
4. Core 未连接时显示 `Core unavailable`，不得播放假进度；
5. 完成后出现 Stem 卡片：人声、伴奏，或四轨结果；
6. 每个 Stem 都提供 `播放`、`静音`、`独奏`、`下载`；
7. 下一主动作变为 `制作伴奏`。

### 路径 B：我要唱这首歌

用户点击 `演唱`。

- 如果伴奏已存在：直接进入演唱准备页；
- 如果只有原作：弹出最短路径选择：`先制作伴奏` / `使用外部伴奏`；
- 不要求用户先理解 Work、Performance、Take 等数据术语。

演唱准备页只展示：

- 伴奏选择；
- 歌词（可选）；
- 输入设备；
- 耳返开关；
- 主按钮 `开始录制`。

### 路径 C：我只是管理或导出

用户可以不分轨、不演唱，直接：

- 修改歌名、封面、作者和来源；
- 查看原始文件信息；
- 导出原始音频；
- 删除自己的 Work；
- 查看处理历史。

## 4. 图标与按钮规则

### 4.1 图标不是装饰

每个图标必须对应一个稳定动作：

| 图标语义 | 动作 | 不得表示 |
|---|---|---|
| 分层波形 | 分轨 | 泛指“AI” |
| 人声轮廓 | 人声 Stem | 完成的真人演唱 |
| 乐器/波形 | 伴奏 Stem | 已验证成品 |
| 麦克风 | 录制 Vocal Take | 自动发布 |
| 叠层卡片 | Performance 版本 | 覆盖原作 |
| 对勾圆环 | 已通过复检 | 仅仅处理结束 |
| 云/公开标记 | 同步或公开 | 本地保存 |
| 下载箭头 | 导出资产 | 发布 |

图标旁默认保留 2–4 个字的动作标签。除播放、暂停、更多菜单等高度通用图标外，不使用只有图标、没有名称的关键操作。

### 4.2 按钮层级

- 每个页面最多一个高亮主按钮。
- 主按钮表示“当前最合理的下一步”，例如 `开始分轨`、`开始录制`、`保存版本`。
- 次按钮用于取消、返回、试听、改名和下载。
- 危险动作使用文字确认，不用高亮绿色。
- 不用“下一步”作为按钮名，按钮必须写明动作。

## 5. 完整产品流程

### 5.1 导入 Upload

**入口：** 顶部 `＋ 导入音乐`  
**结果：** 创建 Work 草稿、保存原始音频、进入作品操作台。  
**状态：** 上传中 / 已导入 / 上传失败。  
**失败处理：** 保留重试入口，不创建伪成功 Work。

### 5.2 作品 Work

**用户看到：** 歌名、封面、时长、来源状态、原作播放器。  
**主动作：** `分轨`、`演唱`、`导出`。  
**系统职责：** 原作成为后续所有派生资产的追溯根节点。

### 5.3 分轨 Separate

**主动作：** `开始分轨`。  
**产物：** Stem，不覆盖原作。  
**完成动作：** `制作伴奏` 或逐轨试听。  
**诚实状态：** Pending / Running / Failed / Core unavailable / Completed。

### 5.4 准备伴奏 Accompaniment

**用户看到：** 各 Stem 的播放、静音、独奏和电平。  
**主动作：** `保存伴奏`。  
**原则：** 伴奏是 Work 的派生资产，不创建新的 Work，也不覆盖 Stem。

### 5.5 演唱 Sing

**主动作：** `开始录制`。  
**录制过程中：** `暂停`、`继续`、`结束`。  
**结果：** 每次录制生成独立 Vocal Take。原始 Take 不被修音结果覆盖。

### 5.6 选择版本 Performance

**用户看到：** Take 01、Take 02……及各自试听按钮。  
**动作：** `设为主唱`、`删除`、`再录一遍`。  
**主动作：** `创建演唱版本`。  
**结果：** Performance 关联 Work 和所选 Vocal Take。

### 5.7 处理与复检 Verify

**用户看到：** 原版与处理版 A/B 试听、处理状态、明确的复检结论。  
**动作：** `保留原版`、`接受处理版`、`重新处理`。  
**原则：** 处理完成不等于验证通过；证据不足时保留当前基准。

### 5.8 保存与发布 Publish

**主动作：** `保存到我的演唱`。  
**可选动作：** `提交发布`。  
**当前未接通云同步时：** 显示 `Pending`，不得显示“已发布”。  
**数据关系：** 一个 Work 可以有多个 Performance，一个 Performance 可以保留多个 Vocal Take。

## 6. 状态反馈规范

任何异步动作都必须在原按钮位置反馈，不让用户去别处猜进度。

| 状态 | 按钮示例 | 页面反馈 |
|---|---|---|
| 可开始 | `开始分轨` | 主色实心按钮 |
| 运行中 | `分轨中 36%` | 进度环，可离开页面 |
| 等待 Core | `等待处理` | 中性样式，并解释依赖 |
| 失败 | `重试分轨` | 显示可理解原因及错误编号 |
| 完成 | `试听分轨` | 出现产物卡片 |
| 需用户决定 | `选择版本` | 不自动接受处理结果 |

## 7. 文案原则

界面文案应当是动作，不是产品宣言。

应使用：

- `分轨`
- `开始分轨`
- `制作伴奏`
- `开始录制`
- `再录一遍`
- `选择这个版本`
- `保存到我的演唱`

避免使用：

- `先让文件成为作品`
- `把完整音频打开为声音层`
- `建立一个可追溯的对象`
- `进入下一阶段`
- `AI 正在赋予音乐生命`

产品理念可以存在于官网和帮助页，但不应占据用户正在工作的主画布。

## 8. 第一版界面实施优先级

### P0：立即完成

1. 删除主画布中的步骤编号、大标题和说明段落；
2. 保留歌名、播放器、状态和四个主动作；
3. 实现 `分轨` 按钮及真实 Pending / Unavailable 状态；
4. 实现 `演唱` 的前置条件提示；
5. 让右侧说明栏改为可收起的详情面板，默认不占据主要操作空间。

### P1：Core 接通后

1. Stem 试听卡片；
2. 伴奏保存；
3. 多 Take 录制与管理；
4. Performance 版本选择；
5. A/B 复检与发布状态。

## 9. 验收标准

让一名第一次使用 Sonviaf 的用户导入歌曲后，在不阅读帮助文档的情况下：

1. 5 秒内找到播放按钮；
2. 10 秒内理解可以分轨或演唱；
3. 能预测点击 `分轨` 后会发生什么；
4. 能区分原作、Stem、Vocal Take 和演唱版本；
5. 不会误以为上传后已经自动分轨；
6. 不会误以为 Pending 已经发布；
7. 始终能够导出或删除自己拥有的原始资产。

达到以上标准，界面才真正承载 Sonviaf 的生产关系：生成音乐是源头，Work 是资产中心，分轨创造可操作性，真人演唱形成新的 Performance，而用户始终拥有原始资产与最终决定权。
